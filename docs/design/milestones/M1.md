# M1 — Guest shell parity · acceptance checklist (awaiting approval)

Status: **checklist only. Not authorised for implementation.**
Baseline: `cursor/playground-220d` @ `5d89fbd` (frozen). Audit source:
`docs/design/PROTOTYPE_COMPARISON_2026-10-18.md` (DV-1, DV-4; §4.1 item 3
approved as design direction on 2026-10-18).

## 1. Objective

Every guest-reachable page renders the same navigation shell as the
signed-in pages: the five-tab bottom bar on phone and the new top nav on
desktop, exactly as the 18 Oct prototypes draw them for `viewer=guest`.
Page content, authentication, legal pages and accepted functionality are
untouched. Authentication gates are preserved: tabs that lead to gated
routes (`/calendar`, `/dashboard` where it redirects today) keep today's
redirect-to-login behaviour.

## 5. Accessibility tests

- Both navs are `<nav>` with distinct `aria-label`s; exactly one
  `aria-current="page"` per nav per page.
- Keyboard: Tab order reaches every tab link; focus ring visible on light
  and dark (contrast ≥ 3:1 against the bar background).
- Tab labels are text, not icon-only; icons `aria-hidden`.
- Contrast: inactive tab text ≥ 4.5:1 in both themes (measure the
  prototype's grey; if below, use the nearest passing shade and record it).
- Bar height ≥ 56 px, hit targets ≥ 44×44 px.
- Automated: a template test asserting the aria attributes; manual axe or
  Lighthouse accessibility pass on R2, R5, R6, R9, R12 (report scores in
  the evidence folder).
